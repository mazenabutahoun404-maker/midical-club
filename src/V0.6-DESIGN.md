# MedClub V0.6 design notes

## Direction

V0.6 extends the medical red/russet system with two related visual metaphors:

- **Mentorship as a guided clinical pathway:** measured pulse lines, connected points and calm directional movement.
- **Scientific review as a safety gate:** staged checkpoints, status rings and clear locked states.

Motion supports meaning. Hovered and active mentorship icons respond like short clinical signals; route reveals remain brief; status changes use restrained emphasis. `prefers-reduced-motion` removes decorative motion without hiding state.

## Information hierarchy

Mentor cards lead with identity, specialty, mentoring areas, capacity and request state. Group-session cards lead with topic, time, format and remaining capacity. The personal workspace separates active plans from discovery so the student can understand what has actually been requested or joined.

Contribution cards always expose current status, last update and next available action. Reviewer feedback appears before revision controls when changes are requested. Approval and publication are visually and functionally distinct.

## Trust boundaries

- Illustrative mentor data is labelled and must be verified before launch.
- Q&A includes an educational-only boundary and should never invite personal health details.
- Rights/reference fields are visible because scientific trust is part of the interaction, not hidden administration.
- Locked under-review and approved states prevent misleading local edits.
- No student-facing publish action exists.

## Responsive and RTL behavior

Desktop retains the collapsible vertical rail and optional horizontal preference. Phones retain horizontal bottom navigation and put secondary destinations in the personal menu. Grids collapse to one column without changing source order. Logical CSS properties and bilingual messages support RTL; scroll cues follow the available direction rather than assuming left-to-right.

## Future API handoff

The screens communicate workflow state but never claim server authority. Real-time capacity, mentor availability, reviewer identity, publication and notifications must come from authenticated services. The current local adapters are explicitly preview infrastructure.
