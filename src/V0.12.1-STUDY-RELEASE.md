# V0.12.1 — Navigation and academic notebook

This is the requested UI/study refinement of V0.12. It does not advance or replace the planned V0.13 analytics milestone. The complete V0.1–V0.12 source remains included.

## Scope

- Main public navigation retreats on downward scrolling and returns on upward intent. Pages with secondary navigation also retract after entry. The personal rail uses this behavior inside course pages; Admin navigation remains unchanged.
- A labeled, illuminated edge handle supports pointer hover, keyboard focus and tap. Navigation can be pinned. Small scroll changes are ignored; navigation interactions, dialogs and menus prevent automatic dismissal. Hidden navigation is inert.
- Section pages allocate their reading space independently of transient navigation visibility. Scroll-driven reveals overlay content instead of changing its width. Horizontal, vertical, mobile and RTL navigation are supported.
- Course sections become an academic notebook with dimensional cover surfaces, a metallic binding, page-stack edges, paper bookmarks and directional 320 ms page turns. The text remains a flat, single accessible content tree. Course accents are preserved: russet, red, olive and purple.
- Bookmarks show the real count and first resource title before interaction. Hover/focus previews show section content, resource names and available metadata. Escape dismisses previews. Touch selection opens directly.
- The notebook remembers the active section, selected material, relative section scroll, reader scroll, explicit PDF page bookmark, supplied recording playback time and split-view preferences per account and course, locally on this device.
- Study focus retains the course title and section controls, reduces surrounding UI and turns off notebook animation. Escape or the visible exit control restores normal study mode. Focus does not carry into another route.
- Split view allows a manually chosen companion resource. It remains independent of the primary section, so a recording can stay beside notes. Wide layouts have an accessible width slider; narrower layouts stack the readers.
- Resource previews use supplied excerpts/thumbnails/chapters when available, otherwise the existing description. Contributor and update metadata are retained; missing reviewer/reference information is explicitly identified.
- Existing save, details, reviewed-state and preview-history actions remain integrated.

Connected learning materials were explicitly excluded. No automatic links between related lectures, slides, notes or questions were added.

## Files and playback

The supplied V0.12 seed resources have `fileUrl: null`. No educational documents, recording contents, excerpts, reviewer identities or references were fabricated. Those resources display their existing descriptions and an honest file-unavailable state.

Resource fields added as optional API data:

```ts
mediaType?: "video" | "audio" | "pdf" | "image" | "external";
preview?: {
  excerpt?: Text;
  thumbnailUrl?: string;
  chapters?: { title: Text; seconds: number }[];
};
reviewer?: Text;
references?: { title: Text; url?: string }[];
```

Provide a real `fileUrl` and preferably an explicit `mediaType` for inline reading/playback. Recognized file extensions provide a fallback; arbitrary external pages open as links instead of being embedded. Native audio/video use controls, metadata-only preload and no autoplay. Only selected material/companion viewers mount. The original-file link remains available for unsupported formats or embedding restrictions.

PDF page state uses the visible page-bookmark input. The browser's native PDF viewer does not expose internal scroll/page changes to this React app; those changes cannot be captured automatically. PDF support depends on the browser; use the original-file link where necessary. Live playback/network performance still depends on the supplied media host and files.

## Persistence and performance

- `medclub:study:v1:<encoded-account>:<encoded-course>` stores study preferences and positions. Guest positions have their own key. It is a device-local convenience, not a backend record or authorization layer.
- Position events update refs rather than rerendering the notebook on every scroll/time tick. Writes are debounced; visibility/page-hide/unmount flush remaining positions. Corrupt or invalid stored values are normalized safely. Storage failures preserve the currently mounted session state and show a session-only notice.
- `medclub:navigation:pinned:v1` stores the device's navigation pin preference. Existing workspace/auth/storage keys are unchanged.
- No new packages, models, raster textures, WebGL canvas or animation-frame loop were added. The notebook uses CSS 3D transforms on functional page layers; this is not a Blender asset.
- Notebook JS and CSS are loaded with the existing lazy CoursePage route. Navigation scroll listeners use a single pending frame and passive events. Reduced-motion and forced-colors variants are included.
- The inherited shared main-bundle size warning remains. Build configuration is deliberately unchanged in this source-only delivery.
