# MedClub V0.13.41 — Campus auth and PDF page choice

Complete source folder based on V0.13.40. Changes cover the requested campus animation, dark building treatment, homepage course books, authentication layout and form effects, and large-screen PDF layout choice.

## Campus and homepage

- Removed the visible pause/resume and replay controls. Homepage and sign-in scenes automatically run a short six-building sequence when visible, then repeat approximately once per minute. Hidden tabs and offscreen scenes do not run the sequence. Operating-system reduced-motion preferences remain supported.
- Removed SVG plaque rectangles behind building names, including the dark-mode backing. Hover and press no longer wash buildings with a pale polygon. Names sit directly on the artwork; keyboard focus retains a theme-colored polygon outline and real destination links remain in place.
- Homepage study materials now open on a shelf of four existing `CourseCard` leather books, with the same cover, spine, pages, opening response and course destinations used elsewhere. The Resources tab retains the existing resource collection, filters and save-to-library flight animation.

## Authentication

- New day/night campus artwork curves six buildings around an open central plaza. The form occupies the centre, with the scene filling the page instead of sitting in a small side gallery. The accepted original campus composition provides the narrow-screen crop. Arabic mirrors the artwork while counter-mirroring its labels.
- Registration starts with the abandoned scene. The new desktop day/night abandoned artwork has its path and building lights switched off. Valid, visited fields reveal their corresponding paths and brief local building effects; the scene gradually crossfades into the restored campus.
- The six milestones are name, valid email, batch, study year, a password meeting the existing rules, and matching confirmation. Clearing or invalidating a field withdraws its milestone. Continuing past the details step accepts the existing batch/year defaults. Back/Edit retains entered values and progress. Verification retains the completed scene.
- A valid sign-in submission triggers a rapid welcome sequence through all six buildings. It is bounded to 900ms and waits alongside the existing authentication request. Failed authentication stops the welcome effect and retains retry controls. Reduced motion or hiding the document removes the visual wait.
- The outer auth page occupies one viewport. Normal phone, tablet and laptop layouts fit their actions in that view, including 320 × 568. Extremely short landscape views, zoomed layouts, keyboard-open views and expanded help/error content can scroll inside the form frame to keep every control reachable. The outer page stays fixed. Viewport resizing follows `visualViewport` where available.
- Existing authentication, registration, recovery, verification, demo-account behavior and safe return destinations remain connected to their existing services.

## PDF reader

- A page-layout button appears when the main reading viewport can accommodate a spread (at least 860px). It switches between one page and two pages using the existing custom arrow tooltip and localized accessible label.
- The logical current page is retained. Two-page mode displays the spread containing that page; switching back displays that exact page. Single-page turns advance one page.
- The preference is stored under `medclub.pdf.page-layout.v1`. Narrow and companion readers remain single-page automatically. Storage failures leave the current reader usable.
- Layout changes retain the open PDF document and raster pool. Only layout-dependent page geometry/display preparation changes. Zoom, colors, search, bookmarks, note controls and the existing page-turn pipeline remain in place.

## Assets and integration

Eight new local WebP assets provide four plaza scenes at 1672px and 960px, totaling 2,449,682 bytes. They are bundled with this source folder. The scene effects use SVG and CSS; this update adds no runtime dependencies.

Back up your existing `src`, then replace it with this complete `src` folder inside your existing React + TypeScript + Vite + Tailwind CSS 4 project. Existing build configuration and service integration remain in use. The browser-local authentication adapter remains the existing preview adapter.
