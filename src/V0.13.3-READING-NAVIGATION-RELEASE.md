# MedClub V0.13.3 — Reading space and navigation restraint

V0.13.3 refines the V0.13.2 interaction system around two principles: study files need a generous reading surface, and motion should explain a destination rather than decorate every control. Every V0.1–V0.13.2 route, workflow, permission and data boundary remains available.

## Larger PDF reading surface

- PDF documents use a tall responsive viewport instead of the previous short embedded window.
- The primary PDF reader avoids a second constrained scrolling region, leaving document scrolling to the native PDF viewer.
- Single-pane, split-view and mobile modes receive separate height limits so the document remains useful without breaking the notebook layout.
- The existing page bookmark, open-file fallback, save state, review state and reading-position behavior remain intact.

## Restrained, semantic icon motion

- Morphing is limited to actual navigation destinations and filter tabs.
- Expand, collapse, hide, pin, search, language, appearance and header utility icons remain visually stable.
- Each mapped destination icon has its own active form; unrelated tabs no longer converge on the same generic checkmark or repeated symbol.
- Reduced-motion mode changes icon state without animation.

## Fixed navigation controls

- The main desktop navigation remains fixed to the viewport.
- Pin and hide controls now live inside the navigation panel instead of occupying a separate outer rail.
- On fine pointers, the controls appear when the navigation is hovered or keyboard focus enters it.
- Touch and coarse-pointer layouts keep the controls visible because hover is unavailable.
- The hidden-navigation edge handle remains available for restoring the navigation.

## Responsive and performance boundaries

- The update uses the existing Lucide icons, semantic HTML and CSS transforms; no runtime animation or 3D dependency is added.
- Route-level lazy loading remains unchanged.
- RTL, keyboard focus, forced colors, touch input and reduced motion remain supported.
- The PDF viewer uses native browser rendering, so its toolbar and exact pagination behavior remain browser-dependent.

## Verification

- 213 automated checks cover V0.1–V0.13.3 behavior.
- Strict TypeScript validation and the production Vite build are release gates.
- Real-browser visual acceptance remains required after integrating the source into its host project.
