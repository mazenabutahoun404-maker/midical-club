# MedClub V0.13.57 — Living Anatomy

Complete replacement `src` folder, based on V0.13.56. Keep the existing React, Vite, Tailwind CSS 4 and Three.js project dependencies. No new package is required. No deployment or API integration is included.

## Changes

- **Medical auth:** a local, real 3D heart sculpture, soft theme lighting, subtle pulse, pointer response and six fine light paths. The scene and form share one background. Arabic reverses the desktop composition. On phones, a compact scene sits above the form; short viewports and the on-screen keyboard reduce the artwork. The form has its own scroll area when needed so fields, validation and actions remain reachable.
- **Registration:** the same two-step flow and validation are retained. Each valid, touched detail reveals a corresponding path and a small starburst where it reaches the heart. Values survive step changes and failed requests. The effect represents form completion, not medical measurements or account verification.
- **Sign-in:** a pending request has its own scene state. A quick path sweep and light response happen only after the service resolves successfully, followed by the existing return destination. The welcome transition is bounded to 420 ms and skipped with reduced motion or a hidden tab. Inputs cannot change during submission. Recovery, verification, demo credentials and existing service contracts are preserved.
- **Medical identity:** a medical-student signature in the homepage hero and small heart, neuron, molecule and stethoscope marks on section headings. Clean sans-serif section titles. Existing page structure, theme choices, dashboard color identities, and three-building Learning / Media / Community campus remain.
- **Phone navigation:** Home, Courses, central Search, Community and Profile. Home remains physically left and Profile right in both languages, as previously requested. More contains Exams and the other destinations, with Get involved first and Store second, without repeating dock links. Existing dock interaction and menu transitions remain.

## Performance and fallback

The Three.js renderer is dynamically imported only for auth, after the form mounts. The model is about 1.02 MiB, has one mesh and 59,959 triangles, and has no textures. A matching 31 KiB WebP poster displays immediately. The existing Three.js dependency is used; the production renderer chunk is separate from the main entry.

The scene renders at most 30 frames per second, limits pixel density, uses no shadows or postprocessing, and reads layout only when resizing or entering the pointer area. Hidden and off-screen scenes stop rendering. Unmounts, aborted initialization, asset failures and rendering failures dispose resources. Reduced motion, data saving, low reported device capability, and missing WebGL2 use the poster. A small SVG fallback remains if that image fails too. All visual assets are local; no external model-host request is made by the running app.

Source and public-domain license details: [assets/medical/NOTICE.md](./assets/medical/NOTICE.md). The sculpture is decorative, not validated instructional anatomy.

## Retained from V0.13.56

The direct searchable course directory, optional year/batch filters, readable book sizing, pinned sidebar default, phone PDF zoom controls and pinch preview are included unchanged. Existing exams, PDF engine, account adapters, routes and API contracts are retained.

## Validation

- Strict TypeScript check and production Vite build pass.
- Fourteen DOM/component groups cover English and Arabic registration, six milestones, error handling, focus, verification routing, pending and failed sign-in, return destinations, renderer/poster fallbacks, reduced motion, cleanup, phone menu priorities and deduplication, decorative SVG IDs, and recovery.
- Four renderer tests exercise real scene/geometry code with a simulated GPU renderer: frame throttling and visibility, abort disposal, render failure, asset failure, and cancelled initialization.
- The real GLTFLoader parses the packaged local model; finite geometry, mesh count and binary integrity are verified.
- The complete source archive is checked against its working files; PDF, learning and service code is byte-compared against V0.13.56.

These are source/build and simulated DOM/GPU checks. Browser layout, actual GPU appearance, physical phone keyboards, pinch gestures and live iOS/Android performance were **not** verified in this session. Review those on real devices before deployment. Vite reports large chunks, including the pre-existing main bundle and the deferred Three.js chunk; it is a warning, not a build error.

## Integrate

Back up your current `src`, replace it with this entire `src` directory, and run your usual typecheck and production build. The existing Tailwind 4 PostCSS/Vite configuration is required. Test auth and navigation in English and Arabic, light and dark modes, and on a real phone.
