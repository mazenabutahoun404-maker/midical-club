# MedClub V0.13.2 — Interaction fidelity and PDF materials

V0.13.2 replaces generic motion with meaningful state changes and rebuilds the course experience around real file-based study materials. Every V0.1–V0.13.1 route, workflow, permission and data boundary remains available.

## Semantic navigation motion

- Navigation icons now contain an initial and destination SVG shape rather than relying on rotation or shaking.
- Bookmark, bell, calendar, search, medical, profile, store and Admin controls receive purpose-specific state changes.
- The shared morph registry matches icons by name so source icons remain owned by their route and the application shell does not import a second copy of every icon.
- Hover, focus-visible and active states share the same visual grammar; reduced motion switches immediately between states.

## Physical discovery surfaces

- Course catalogue entries are closed three-dimensional academic volumes with a spine, page block, inset cover, ribbon and a cover palette derived from each course theme.
- Hover opens the cover only enough to reveal the first-page preview while keeping the complete card as one accessible link.
- Event and opportunity cards now lift as file folders, move a colored divider, reveal secondary information from a sheet behind the face and strengthen the primary action.
- Coarse-pointer and narrow layouts keep all revealed information visible without depending on hover.

## Real notebook behavior

- Course section changes preserve the outer-page position instead of forcing the page back to the notebook top.
- Both the course header and notebook provide a clear route back to the course catalogue.
- Page turns now include front and back sheet surfaces, a moving edge and a travelling shadow so the direction reads as a page turn rather than a generic fade.
- Existing selected resources, bookmarks, reading position, split view and focus mode remain intact.

## PDF material importing

- Slides, notes, questions and the other file-based sections accept one or more real PDF files through a styled picker or drag-and-drop surface.
- The drop surface gives an explicit drag-ready state and animates a PDF sheet landing into a miniature notebook.
- Files are validated as PDFs, limited to 30 MB each and eight files per import, and stored as Blobs in IndexedDB with a safe in-memory fallback.
- Imported files become normal PDF resources, open inside the existing notebook viewer and can be removed from the active section.
- The importer is shown only to authenticated accounts with review, publishing or builder capability.

## Production boundary

This source-only release stores imported PDFs on the current device. Shared materials, moderation, revision history, permanent URLs and multi-device access require authenticated backend storage plus server-side permission and scientific-review enforcement. The UI and repository boundary are ready for that replacement; no device-local upload is presented as a published club resource.

## Performance and accessibility

- No 3D library, WebGL scene, Blender model or new runtime dependency is introduced; the physical effects use semantic HTML and GPU-friendly CSS transforms.
- Route-level lazy loading remains intact.
- Fine-pointer hover enhancements have touch fallbacks.
- RTL reverses opening direction and page movement.
- `prefers-reduced-motion`, forced colors and keyboard focus retain complete functionality.

## Verification

- 206 automated checks cover V0.1–V0.13.2 behavior.
- Strict TypeScript validation and the production Vite build are release gates.
- Real-browser visual acceptance remains required after integrating the source into its host project.
