# MedClub V0.13.48 — phone navigation, Notes and RTL repairs

This ZIP contains the complete `src` directory, based on V0.13.47. Replace your existing `src` with this one and keep the current project configuration and dependencies. Every previous source file is retained. No dependency or API connection was added.

## Requested visual repairs

- Book spines and covers share their vertical inset and available height. The small-screen inset changes together for both parts; Arabic retains its right-hand spine and left-hand opening edge. A flexible cover track also keeps the binding aligned when neighboring books have different title lengths.
- Sidebar hover and active backgrounds have rounded corners on both physical sides, including Arabic and collapsed navigation.
- Event tickets use transparent circular cutouts instead of circles painted in the page background color. The silhouette follows the vertical desktop perforation and horizontal phone perforation, in both directions and all themes.
- Arabic opportunity cards mirror the animated circular ornament, ribbon, rounded silhouette and action position. English placement is retained.

## Compact Notes

The floating notebook is now 352px wide at most and 560px tall at most, with smaller note rows and internal scrolling. It has a slim draggable grip attached to its upper border, a title and a single minus action. The duplicate position-reset control, explanatory footer and side restore button were removed. Reopen it from the existing Notes icon in the page or study header.

Hiding keeps the editor mounted and preserves its current draft. Position remains private to the current account and clamped within the visible viewport. The grip supports arrow keys, Shift for larger steps, and Home to reset position. Escape and the minus action hide the notebook. Existing note creation, attachments, PDF-page navigation, editing, deletion and storage boundaries are retained.

The header Notes icon now has its own finite paper-turn and folded-corner response on hover/focus and click. Reduced motion skips these movements.

## Phone navigation

The student/public dock has five icon-only destinations in physical left-to-right order:

**Home · Courses · Search · Exams · Profile**

Home remains at the far left and Profile at the far right in both languages, following the requested endpoints. Search is centered. Accessible labels, visible keyboard focus and 44px touch heights remain; guest Profile opens sign-in with a return to the profile page. The Profile destination also remains a target for the existing save-flight feedback.

A glass selection lens follows hover and horizontal dragging. Releasing a drag inside the dock activates the indicated destination. Vertical gestures scroll normally; cancellation leaves the current route in place. Native link dragging is disabled within this control, and touch-capture transfer is handled without dropping the gesture. Clicks, ordinary taps and keyboard activation still work. Reduced motion removes the lens transition, and an opaque fallback is provided when transparency is reduced or backdrop filtering is unavailable.

Less frequent destinations move to **All sections** in the phone header. Its directory has searchable groups for study tools, personal activity, learning, campus and account links. Existing routes remain available, and the admin entry is conditional on the existing access capability. Desktop navigation retains its usual structure. The admin phone rail adopts the compact glass shape and icon-only captions while preserving its permission-filtered destinations and administration menu.

## Phone overflow

The orders page previously let the intrinsic width of its store navigation expand a grid track beyond the phone. The store grid now has a flexible `minmax(0, 1fr)` track with shrinkable children. This contains the navigation within the page and retains its local horizontal scrolling where necessary. No new global overflow-hiding rule was added; the PDF reader keeps its existing pan/grab behavior.
