# MedClub V0.13.22 — Course chrome and comfortable PDF reading

Replace the entire existing src directory with this archive's src directory. This update starts from the complete V0.13.21 source and adds no runtime dependency or media asset.

## Changes

- The persistent course shelf is mounted at the top edge instead of leaving an empty strip above the books. Its shallow recess, beveled rail and inset highlights give it material depth using the existing theme colors and leather assets. Shelf browsing, current-course selection, 50-book navigation and preserved scroll position remain intact.
- Campus navigation and its reveal controls are unmounted throughout public and personal courses. There is no edge glance, contour, hover target, phone navigation or main header in a course. Programmatic reveal is also blocked. Back to courses remains available outside focus; leaving a course restores normal navigation and keeps the user's existing pin preference.
- The unopened PDF card has an in-flow details dropdown with provenance and review controls. Its favorite icon stays on the card. Open PDF readers, including companion readers, omit the metadata/review/favorite footer. Other media retain their details workflow.
- File actions have bounded 44 px targets. Long English/Arabic titles wrap; on small phones the actions occupy their own row instead of hanging beyond the page. Authorized local-PDF deletion appears on pointer hover or keyboard focus; touch users have visible controls. Import and deletion capabilities retain the existing role checks.
- Successful imports show the existing landing/progress/confirmation sequence, then return to the default upload state after 1.4 seconds. The input clears so the same file can be selected again. Errors remain visible; an unavailable device-storage warning is retained.
- PDF deletion has a short erase transition. Durable deletion waits for the IndexedDB transaction to commit. On failure, the card and object URL remain available and an error is announced; session-only PDFs can still be removed. Duplicate delete clicks are guarded.
- Review and private-note saves show a short ink/check receipt only after successful persistence. Failed saves keep the draft and show the existing error. Reduced-motion preferences remove spatial animation.
- PDFs default to softened paper in dark mode: neutral brightness/contrast adjustment, without inversion. Paper comfort can be changed in the existing reader options; original colors are available for diagrams. Light-mode PDFs remain original unless the user chooses otherwise. This is a display preference, not a modification of the PDF.
- Learn's dropdown chevron is a static, non-interactive SVG inside the destination link. Hover still opens categories, Learn still opens Explore, and keyboard ArrowDown/Escape remains supported. There is no separate chevron button.

## Suggested future palettes

Keep light/dark/system as the base preference, then consider Paper (warm cream and ink), Dusk (muted slate with wine accents), and High contrast. Use a shared token model and verify every text/background pair, status color and PDF reading treatment before adding another palette. No additional application theme was introduced in this release.

## Verification and limitations

- 64 DOM/state checks: 46 preserved or intentionally updated navigation/shelf/study checks and 18 focused file/persistence/reading checks.
- Strict TypeScript and production build pass.
- Source CSS cascade audit passes 90 constraint scenarios and 20 text/background contrast pairs, covering narrow phones, desktop, RTL, hover/focus, touch, reduced motion, bounded file actions and the top-mounted shelf.
- All 679 baseline source files remain present; 663 are byte-identical and 16 were modified. Four runtime/style files and this release note were added, for 684 files.
- Course and PDF engine code remain lazy-loaded. The existing large shared entry-chunk advisory remains at approximately 1,021 kB before gzip.
- The DOM harness uses test-force-exit after awaited assertions and cleanup to discard idle query-cache timers; it does not prove rendered browser geometry, animation smoothness or frame rate.
- Live browser visual acceptance remains unverified. The Sites workflow requires skipping browser QA in the managed environment when its control-browser skill is unavailable.
- PDF imports remain device-local, with the existing session fallback. This update does not add shared publishing or server storage.

Browser acceptance should cover the shelf's top contact and title reveal; long English/Arabic file names; deletion hover/focus/touch reachability; opening primary and companion PDFs; dark paper versus original diagram colors; importer reset and retry; and entering/leaving public/personal courses on narrow phones.
