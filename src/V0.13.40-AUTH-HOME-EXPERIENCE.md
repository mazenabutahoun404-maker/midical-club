# MedClub V0.13.40 — Authentication and homepage experience

This complete source folder builds on V0.13.39. Authentication now has a campus gallery beside a focused form, and the homepage uses distinct chapter layouts with coordinated entrance and scroll effects. Changes are limited to the requested authentication and homepage experience, its assets, and release metadata.

## Authentication

- Sign-in and recovery use the accepted active campus. Registration and verification use the approved abandoned campus, with its weathered buildings, ivy and dormant spaces. Both have responsive day and night artwork.
- Desktop uses a curved form frame beside the campus gallery. English and Arabic exchange sides; translated plaque labels remain readable. The gallery is sized to leave the primary action within the first desktop view. Phones and narrow tablets place the form before the artwork.
- Registration has two steps: personal/academic details, then password and confirmation. Back and Edit preserve entered values. Required fields, email format, password rules and confirmation retain localized error handling; invalid fields receive focus and error associations.
- Sign-in retains password visibility, the preview-account fill action, pending states and error messages. Switching between sign-in and registration preserves the requested return destination.
- Verification and recovery remain connected to the existing authentication service. Recovery failures now display an error instead of leaving a rejected promise unhandled. Theme and language changes retain entered form values.
- Paths visit the six buildings one at a time, with local glows and small sparks. A quiet interval separates cycles. A visible pause/resume control is provided. Decorative buildings do not interrupt the form with navigation.

## Homepage

The accepted hero composition, its real building links, current theme colors and Arabic mirror layout remain. On entry, the welcome copy appears gently and paths reach each building in sequence. Local glows, a globe pulse and brief sparks accompany the sequence. It finishes in about six seconds; the user can pause or replay it. Search and a link to the first available content chapter remain accessible.

Section headings, pathways and records still come from the existing services. CMS enablement, ordering and scheduled visibility remain in use. Empty, loading and error states are retained. Resource filters, event/opportunity save controls, journal routes and the existing save-to-library flight animation remain functional.

The scroll sequence uses rises, side entrances, gentle unfolding and an orbit reveal. Each target reveals once. Asynchronously loaded content is observed too; keyboard focus reveals a target immediately. Content remains visible when IntersectionObserver is unavailable or motion is reduced.

## Motion and integration

Campus effects use the approved artwork plus live SVG overlays; no new WebGL renderer or package dependency is added. Building hit areas, paths and image geometry share the same coordinates. Timing uses a single scheduled cue rather than a continuous JavaScript rendering loop. Timers stop offscreen, while the document is hidden, when paused, and for reduced motion. Existing pointer movement retains its cached geometry and queued frame updates.

Back up and replace the existing `src` with this entire folder. Retain the project's configuration and dependencies. The authentication provider, service contracts, storage keys, route journey and backend adapter are unchanged. The existing authentication adapter remains the project's device-local preview implementation; this release does not add server authentication or email delivery.

Earlier reader/PDF fixes, notes, navigation, dashboard themes, notification/translation icon effects and save-animation implementation remain byte-identical to V0.13.39. Global styles and shared card implementations are unchanged; the new styles are scoped to authentication or the homepage.
