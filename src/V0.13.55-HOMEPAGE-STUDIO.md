# MedClub V0.13.55 — Homepage studio

Complete source based on V0.13.54. Replace the existing `src` folder with the included folder. No dependency or project-configuration changes are required.

## Lower homepage redesign

- Study shortcuts use small folder shapes, distinct theme tints and clear icons instead of a second illustration.
- Courses use a constructed bookcase: an arched inset, a colored ledge and the existing leather books. The room image is removed. Each book retains its fixed outer width and portrait cover ratio; narrow screens browse fewer books at once with the existing native swipe and arrow controls. The covers, bindings, long-title clamp and opening interaction are preserved.
- Get involved has two distinct destinations. Events feature a strong theme-colored ticket with transparent notches, a perforated date stub, clear registration status and two smaller date cards. Opportunities use numbered cards, readable deadlines, status and direct actions. The two feeds retain their CMS order and independent visibility, loading, empty and retry states.
- The journal uses a paper-cover story, a medical seal, an editorial masthead and two numbered reading cards. Article titles, excerpts, authors, dates and detail routes still come from the existing journal service.
- Community uses a small group graphic made from actual mentor initials, the CMS introduction and two main actions. Three mentor profile cards form a stepped directory; the directory stacks cleanly at narrow widths. Empty feeds do not invent people.

## Theme and motion

The new homepage stylesheet is scoped to `.home-studio`. It derives surfaces, edges, readable accent ink and strong fills from the selected palette. It does not alter the global theme system or dashboard identities. Headings and body text remain high in the hierarchy; save controls have a minimum 44px target.

The existing intersection observer triggers short, one-time entrances: books settle onto the shelf, the event ticket moves into place, opportunity cards slide in, and journal pages settle with a slight rotation. Small mentor initials appear in sequence. The effects use opacity and transforms without image blur, continuously running effects or a new JavaScript scroll loop. Keyboard focus reveals the relevant content immediately. Reduced-motion and forced-color fallbacks are included.

## Removed assets and preserved features

Removed all 24 obsolete scene images from `assets/home-scenes-v1350`, the four unused curiosity scenes from `assets/campus-scenes-v1351`, the unused `SectionArt` renderer and the replaced V0.13.54 homepage stylesheet. The removed files total approximately 7.4 MB. This is a source-asset reduction, not a measured loading-time improvement.

The campus hero, authentication artwork, footer buildings and Octagram credit, phone navigation, shared course-book component, bookmark-flight animation, PDF reader, exam engine, service contracts and application routes are unchanged. Historical release notes remain included.

## Validation and limits

- Strict TypeScript checking and the production build pass with the existing dependencies. The existing large-chunk build advisory remains.
- Twenty-six DOM cases cover English and Arabic content, CMS ordering and visibility, schedules, custom headings, empty feeds, event/resource/opportunity/journal/mentor error recovery, direct detail routes and course/resource tab switching.
- Additional DOM checks cover keyboard-triggered reveals, observer cleanup and reduced-motion behavior. These are functional checks without a browser layout engine.
- sRGB calculations check the new strong text surfaces and tinted-surface ink across all 18 palette/mode combinations. The checked text pairs exceed 4.5:1. This is a color calculation, not a rendered-page accessibility audit.
- The responsive CSS keeps the fixed-width shelf, cover aspect ratio and matching binding insets; it uses logical offsets for Arabic and stacks the participation, journal and community areas at narrower breakpoints.
- Browser preview was unavailable in this environment for this revision. Actual geometry, touch interaction, scroll animation appearance and physical Safari/Android behavior were not visually verified. No browser performance improvement is claimed.
