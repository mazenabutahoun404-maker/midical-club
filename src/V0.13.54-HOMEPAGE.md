# MedClub V0.13.54

Complete source based on V0.13.53. Replace the existing `src` folder with the included folder. Existing dependencies and project configuration are sufficient.

## Homepage structure

- The interactive campus hero is preserved. Study shortcuts now provide four compact actions: Courses, Exams, Study Tools and Saved library. The extra curiosity illustration is no longer rendered here.
- Courses keep the library illustration and leather books. The heading identifies the section directly, and the existing resource collection remains available in its own tab.
- Events and Opportunities share one Get involved area: a featured event ticket, two additional dates and three opportunity listings with clear deadlines. Existing detail routes, availability helpers and bookmark controls are used.
- The Medical Journal presents one leading article and two compact article rows. All three articles link directly to their pages.
- Community and mentorship use the existing community copy, two main actions and three mentor profiles from the existing mentorship service. Initials come from those profiles. The repeated six-building map is no longer rendered here.
- The large decorative event, opportunity, journal and community scenes are no longer mounted. The campus and library remain the large visual features. Footer artwork and Octagram credit are unchanged.

Default homepage labels and shortcut content were updated in the mock site record. Custom content from the existing site service remains supported. Enabled/scheduled sections and their order are respected; Events and Opportunities are grouped at the first visible participation section. Both enabled anchor IDs remain usable, and either feed can be hidden independently.

## Book proportions

Books no longer use four fractional grid columns. Each volume has a 304px outer width at normal viewport sizes, with no flex shrinking. Only narrow phones reduce that width to fit their screen. Covers keep a 0.7 width-to-height ratio, and the spine uses the same block inset as its cover.

The shelf uses native horizontal scrolling, touch swiping, focus scrolling and previous/next controls in both languages. The buttons advance one book and become disabled at the ends. A short walnut surface sits directly below the books. Long course names occupy up to two lines; their full text remains in the accessible HTML and course detail page. Smaller cover descriptions are condensed on the narrowest phones.

The library uses its larger existing image source for the tall phone crop. No new artwork or image blur is introduced. Existing cover opening and bookmark-flight animations are preserved.

## Loading and interaction

One 220ms fade with a small vertical movement is used across the lower sections, with reduced-motion support. New section layouts use the existing theme colors and solid surfaces for readable content. The hero's lighting, theme behavior, phone menu, notes, PDF reader and exam engine are unchanged.

Course content remains usable when the resource feed fails. Events and Opportunities have independent loading/error states and retry actions. Empty feeds display empty states, and an empty mentor feed does not invent people. The existing service contracts remain the boundary for future API integration.

## Validation

- Strict TypeScript checking and the production build pass using the existing project dependencies.
- Chromium automation covers 24 English/Arabic, light/dark layouts at widths of 320, 390, 768, 1024, 1440 and 1920px. The books retain their cover proportions, the spine stays aligned, shelf controls work in both directions, and the document has no horizontal overflow in those cases.
- Eighteen CMS and service cases cover independently hidden or scheduled participation feeds, reordered sections, custom headings and shortcuts, empty feeds, separate error states and successful retries in both languages.
- Eight additional long-title cases verify English and Arabic cover text on narrow phones through desktop widths. Five palette cases cover Sage, Espresso and Midnight.
- Browser checks exercise the existing bookmark flight, event/opportunity/article/mentor/course detail links, guest sign-in return to Saved library, and the retained phone priority menu.
- A Chromium trace of eight bookshelf moves and four content-tab switches records no long-layout or long-task violations, console errors, page errors or new network requests during those interactions. This is a local check, not a device-wide performance guarantee.
- Every V0.13.53 source path is retained. The hero, footer, shared course-book component, phone navigation, PDF reader and exam engine source remain unchanged.

These checks use automated Chromium viewports and touch emulation. Physical iOS/Safari and Android devices were not tested in this environment.
