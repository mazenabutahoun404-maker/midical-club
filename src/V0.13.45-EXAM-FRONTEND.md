# MedClub V0.13.45 — integrated exam frontend

This complete `src` folder extends V0.13.44 with the exam-platform frontend inside MedClub. Replace the existing `src` folder, retain the existing project configuration and dependencies, and run TypeScript checking and the production build. No package dependency was added. All V0.13.44 files, campus artwork and PDF-reader code are retained.

## Student experience

- Browse by course, year, sciences and semester, then choose a batch and question set. Assigned courses appear first in My Space. Empty banks have an explicit empty state.
- Practice gives feedback after choosing an answer and preserves that answer. Self test permits changes and reveals feedback after finishing. The suggested duration is guidance, not a proctored deadline.
- Resume the exact question, answers, review flags and elapsed time; save and exit; finish with confirmation. Results include question review, explanations, correct/incorrect/skipped/flagged filters and previous attempts.
- Save questions, revisit mistakes, search questions within a course and create a focused set using chapter, lecture, instructor and batch filters. Saved-question views request a page of results; the custom-set form requests facets and counts instead of downloading the whole bank.
- Explanations preserve the source platform's formatting, tables, callouts and image slots. Question images can be expanded. Review/print uses browser printing, including Save as PDF where the browser supports it.
- English and Arabic share the MedClub layout and mirror direction-sensitive controls. The new pages inherit the personal brown, admin wine and all existing appearance palettes. The exam navigation becomes a compact tools dialog on phones. During a question session, the bottom app navigation clears the question controls and returns when leaving the session.
- My Space gains an optional exam shortcut without changing the existing default pinned shortcuts. Quick revision can open the current course's exam shelf.

## Content workspace

`/admin/exams` uses MedClub's existing `content.review` capability. Administrators can create question sets, edit localized questions and answer explanations, attach images, validate bulk text imports, publish sets and resolve question reports. Invalid imports are blocked before committing. Deleting questions or sets requires confirmation. Attempts keep question snapshots, so later bank edits or deletion do not change an existing attempt's questions or result.

Existing MedClub login, profiles, roles, users, analytics and other admin pages remain the shared systems; the exam repository's separate versions of those systems were not imported.

## Routes

| Route                                            | Purpose                                        |
| ------------------------------------------------ | ---------------------------------------------- |
| `/learn/electronic-exams`                        | Public course catalogue and exam entry         |
| `/my/exams`                                      | Personal course catalogue and resume action    |
| `…/set/:examId`                                  | Practice/self-test setup                       |
| `…/set/:examId/review`                           | Review a question set                          |
| `…/set/:examId/print`                            | Print a question set                           |
| `…/attempt/:attemptId`                           | Active question session                        |
| `…/attempt/:attemptId/results`                   | Finished session review                        |
| `…/history`, `…/notebook`, `…/wrong`, `…/search` | Attempts, saved questions, mistakes and search |
| `/admin/exams`                                   | Exam content administration                    |

The `…` routes exist beneath both student entry paths. The personal path requires MedClub authentication; the preview public path can also demonstrate the flow as a guest.

## API boundary

No original Next.js API routes, Supabase clients, SQL, API credentials or backend requests were copied. The UI depends on `ExamService` in `types/exams.ts`. A future adapter is injected as `services.exams`; [integration/EXAMS-FRONTEND.md](./integration/EXAMS-FRONTEND.md) documents the contract.

In MedClub's sample configuration, the adapter is a clearly labeled, device-local preview. Its starter questions demonstrate interface actions; they are not a medical question bank. Preview attempts do not grant campus growth or academic-readiness credit. Data stays in the current browser; it does not synchronize across devices. A live MedClub configuration without an exam adapter shows an unavailable state rather than silently displaying preview questions.

The preview separates guest/account attempts, bookmarks and custom sets. Storage denial falls back to the current session with a visible notice. Corrupt stored data reports an error rather than resetting it silently. The session maintains a private recovery draft and serial save queue; version conflicts and save failures offer retry or reload. No future server endpoint or authentication scheme was guessed.

## Performance and verification

- Strict TypeScript checking and the production build passed. Exam UI pages are lazy loaded; no PDF engine is opened by the exam flow.
- 56 hub/session layout checks passed: English/Arabic, light/dark and widths from 320 to 2560 pixels. Checked controls maintained at least 44px height without horizontal page overflow.
- 36 theme checks passed: all nine palettes, both modes and both languages. Sample answer text and primary-button contrast exceeded 4.5:1.
- Student flow checks covered save/resume/reload, exact question restoration, flags/bookmarks, practice and self test, results, mistakes, custom filters, search, printing, keyboard navigation and reduced motion. Admin checks covered creation, editing, image attachment, import validation, publishing, reporting, resolution and confirmed deletion.
- Model checks covered account separation, admin authorization, frozen question snapshots, conflict handling, idempotent finishing, scoring, paged notebooks, unavailable services, storage failure and formatting/import edge cases.
- The timer advanced without any mutations to the question panel. In a controlled mobile Chromium run at fourfold CPU throttling, 12 keyboard page changes took approximately 34–108ms, including automation overhead. These are local observations, not a guarantee for every browser, device or later API.
- The existing My Space scenarios passed. The real eight-page PDF fixture passed 48 balanced-frame checks across both languages, both navigation orientations, six widths and normal/focus modes after layout settling. PDF-reader source and styles were unchanged.

The existing large main application-chunk build warning remains. This release does not connect or test real exam APIs, cross-device persistence or a proctored assessment backend.
