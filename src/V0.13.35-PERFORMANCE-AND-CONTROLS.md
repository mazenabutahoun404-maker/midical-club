# MedClub V0.13.35 — requested performance and control fixes

This complete source release builds on the accepted V0.13.34. Back up the host
project's `src`, then replace it with the enclosed `src` directory. Keep the existing
configuration and dependencies. No dependency is added. No deployment is included.

## Route responsiveness

Navigation commits the destination immediately instead of waiting for a fixed
140 ms exit timer. Lazy modules and query-driven pages keep their loading UI visible
and interactive. Ready content receives a brief, restrained arrival fade. Scroll
restoration, fragment links, keyboard focus and the existing same-desk course switch
remain supported. Height comes from ResizeObserver rather than a synchronous
`offsetHeight` read during navigation. Selection geometry is measured in a queued
frame with persistent observers, avoiding observer teardown and class changes on
every route. Reduced motion still bypasses motion.

## PDF controls and rendering

- Animation progress updates the visual turn leaf independently. The reader tree
  updates at the turn's start, midpoint and finish instead of every animation frame.
  The existing ribbon turn and previous/next keyboard behavior remain.
- The spread and its animated copies share a cached paper-color display raster.
  Paper conversion works in small pixel strips and yields between strips, allowing
  other UI tasks to run. The source raster, colored figures and PDF bytes are intact.
  Original colors is still available. Changing paper tone no longer rebuilds the
  selectable text layer. Search and page-note anchors retain their existing data.
- A single raster job runs at a time. Visible requests precede queued prefetches;
  a visible request promotes an existing prefetch. Evicted queued pages are canceled
  instead of rendering obsolete zoom sizes. Closing rejects queued work, cancels the
  active render and releases cached canvases. Eight source pages remain the cache
  limit, with at most one current paper-color copy for each cached source raster.
- ResizeObserver supplies reader dimensions without immediate post-render width
  reads. Shared study-tool values/callbacks and note arrays stay stable when their
  contents do not change.
- Side turn targets are 44px wide and 120–280px tall, bounded by their reading
  surface. The close control retains its separate 44px toolbar cell. Tooltips remain.
- Section-turn visual snapshots skip the redundant PDF text-selection DOM and cap
  their copied DOM/pixels. These limits apply only to temporary animation faces.
  The live document, notes and resource content are unaffected.

## Navigation and translation

Pin/hide controls remain absolutely positioned over the status row, with no change
in footer height on reveal. Their width is bounded by the row, including the folded
rail. Public, personal, admin, horizontal and RTL layouts use that rule.

The English locale places Arabic above A; the Arabic locale places A above Arabic.
The existing hover/focus exchange animation is retained. Bell feedback, the save
flight to the profile library, bookmark response, study progress motion, palettes,
workspace identities and glass appearance panel are retained.

## Verification and remaining limits

Targeted executable checks cover pixel parity, source preservation, cooperative
paper preparation, shared caching, failed/retried requests, cancellation, memory
cleanup, foreground priority, animation publication counts and both locale orders.
The previous private-note/version/undo and preserved-motion checks also pass.
All 18 palette variants retain their semantic colors and contrast checks. Every
V0.13.34 source file remains present; changes are limited to the requested scope.
Syntax checks pass for changed TypeScript/TSX entries. Strict checks pass for the
new rendering/motion helpers and the isolated turn, snapshot and selection modules.

The upload contains sources without the host package manifest, dependency lockfile
or build configuration. A full production build and live-browser performance trace
could not be run here. Run those in the host project, including rapid navigation,
large PDFs, zoom, search, notes, narrow/touch screens and Arabic RTL. Browser forced
reflow messages are performance diagnostics, not crashes. The changes remove
identified sources of blocking work; they do not suppress diagnostics or establish
that every warning has disappeared. PDF.js and browser layout can still perform
necessary measurements.
