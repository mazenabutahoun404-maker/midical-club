# MedClub V0.13.36 — PDF loading, controls and page turns

This complete `src` release builds on V0.13.35. Back up the host project's `src`,
then replace it with the enclosed directory. Retain the host configuration and
dependencies. No package dependency is added. No deployment is included.

## Loading and document lifetime

The PDF engine imports its 198 bundled CMap/font/WASM asset URLs lazily. It loads
an asset when PDF.js requests it instead of eagerly importing all asset modules
when the reader opens. The bundled support assets remain in the source.
Canceled reader effects are checked before creating a loading task, including
React development StrictMode's initial setup/cleanup replay.

The document-opening effect depends on the file URL and an explicit retry. Page
turns, zoom, searching, bookmarking, notes and paper colors do not reopen the file.
Closing or changing files still destroys the loading task, cancels rendering and
releases owned caches and worker resources.

## Stable page display

Raster identity is independent of zoom. Pages are prepared for the reader's maximum
zoom and scaled for display, including the transparent text-selection stage. Zoom
no longer clears/rebuilds canvas pixels or reconstructs text spans. A real width or
spread-layout change can still require a different raster.

The renderer exposes a synchronous lookup for ready display pixels. Cached pages
are painted before the frame is displayed, avoiding a loading flash when returning
to a prepared page. The next spread's complete display rasters are prepared before
the existing ribbon animation starts. The current spread stays visible while a
cold destination is being prepared, and stale preparations cannot commit after
the file, page, layout or appearance changes. Nearby-page prefetch includes paper
colors rather than only the original white source raster.

The ribbon's position moves with a transform instead of an animated `left`
property. The active PDF turn allocates its visual layers only for its lifetime.
The existing page-turn appearance, direction, keyboard controls and reduced-motion
behavior remain.

## Text and color preparation

Visible raster completion no longer waits for text extraction. Text data and
selection DOM have their own caches. TextLayer receives a ReadableStream in batches
of at most 80 items, yielding a UI task between batches. This uses the streaming
interface already implemented by the bundled, unmodified PDF.js 6.4.299; its narrow
TypeScript declaration now describes that interface. Dense pages do not create all
selection spans in one synchronous task. Cached selection DOM is reused when a
page returns. Search uses cached text and yields during a multi-page scan.

Where Worker, OffscreenCanvas and ImageBitmap are available, a reader-owned worker
converts neutral paper/ink pixels off the UI thread. The main thread transfers the
result to a display canvas. Source PDF bytes, original rasters and strongly colored
figure pixels remain intact. A blocked/unsupported worker falls back to the existing
cooperative pixel-strip conversion. Worker errors, cancellation, pending requests,
late responses and bitmap transfers have explicit cleanup. Original colors remains
available. Changing paper colors does not rebuild the text layer.

The existing limits remain: eight source rasters, at most one current toned display
copy per source, and one active raster job. Ready-display lookups are bounded to
16 entries. Text data is bounded to 16 pages; selection DOM is released with its
source page. The larger page-turn targets and separate close-button cell are kept.

## Preserved features

All V0.13.35 files remain present. Changes are limited to the PDF performance path,
its types and release documentation. Themes, dashboard colors, navigation controls,
language ordering, bell animation, liquid-glass appearance, course notes/anchors,
private-note storage, bookmarking and the profile-library save flight are retained.

## Verification and limits

React DOM interaction checks exercise the real PdfBook/usePageTurn components with
a mocked DOM and PDF engine in single-page, two-page and Arabic RTL configurations.
They verify one document open per file, no raster rebuild or canvas repaint for
zoom/search/bookmark controls, correct page-turn commits, appearance-only updates,
file replacement and close cleanup. The same harness on V0.13.35 reproduces two
initial opens in development StrictMode and new raster requests/canvas repaint on
zoom; the updated reader removes those operations in the harness.

Executable checks also cover pixel parity, the actual worker message handler,
transfer failure, worker fallback/disposal, dense text order/positions, streamed
text cancellation, selection-cache reuse, raster readiness independent of text,
ready-display invalidation and stable raster geometry across all zoom values.
Previous private-note/version/undo and preserved-motion checks remain passing.
Changed TS/TSX entries pass syntax checks; isolated rendering/worker/text/geometry
and turn helpers pass strict TypeScript checks.

The upload is source-only and lacks the host package manifest, dependency lockfile
and build configuration. A full production build or live-browser performance trace
could not be run here. These checks establish the changed lifecycle/rendering
behavior; they do not establish real-browser frame times or guarantee that every
performance warning disappears. File/network speed and PDF complexity still affect
cold loading. Similarweb extension CORS/connection errors are outside this reader.
