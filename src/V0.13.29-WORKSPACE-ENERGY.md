# MedClub V0.13.29 — Reader controls and workspace identity

Replace the complete `src/` directory. No dependency was added. This source-only release preserves all V0.13.28 files, routes, local records, and backend adapter boundaries.

## Changes

- Public header: preferences, Search, Notifications, account. Bell is immediately adjacent to Search; search expands into the available side space from the clicked icon. The personal header retains its Search → Notifications order. Appearance is still absent from the personal header and available in the sidebar/phone More.
- Profile/account controls have a stronger bordered surface than utility buttons. The permission-gated Admin shortcut regains its wine/violet/gold treatment, soft aura and one-shot hover shine without becoming another primary navigation tab.
- Sign-out is explicitly red. The SVG door opens around its hinge and reveals a person stepping into the doorway on hover/focus. Motion is localized and honors reduced motion.
- Downloaded PDFs now load their own page, turn, pan, and toolbar styles. Rendering no longer relies on first visiting a course. Desktop controls stay in one aligned row; narrower readers use one PDF-tools menu. Theme paper, Original colors, search, zoom, bookmarking, margin notes and finite PDF-page boundaries remain.
- Closing course sections removes their 44px grid row, makes the hidden rail inert, and gives the space to the reader. Reopen lives inside PDF tools while reading, rather than another floating close/reopen control. Section-only views have a normal Sections control. Arabic and focus-mode exits remain available.
- The search field has a single outer focus boundary; the duplicate inner red ring is removed. Background blur drops from 5px to 2px. Immediate typing and icon-anchored placement are preserved.
- Light MedClub chrome uses the actual `#a50f15` brand red with white text. Other light palettes have distinct warm paper, blue, violet or teal chrome accents. Calm page gradients add color around the main layout while PDF paper stays controlled by the reading palette. Existing dark palettes and high-contrast support remain.
- Four study cards now have purpose-specific objects and details: layered question cards, a document folder, a shared study table, and an achievement certificate. Their short intent animations do not loop. Save/edit/review feedback and existing trash/Undo flows remain.

## What the tools mean for a student

- **Active recall** (formerly Recall desk): write your own question and answer, attempt it from memory, then reveal the answer. Your Again/Hard/Good/Easy rating schedules the next review; it is not a diagnosis or grade of your ability.
- **Verified achievements** (formerly Campus portfolio): record publications, activities, volunteering and leadership with evidence. Submit for a permitted reviewer; only verified achievements enter the optional shared portfolio. Sharing can be disabled and verification can be revoked.
- **Study together** (formerly Quiet study rooms): invite classmates into a quiet room with actual members, personal goals, recent presence, and one shared focus/break timer. The host controls the session. It is a co-study room, without chat or camera.
- **Offline course packs**: store permitted course PDF snapshots on this device with their margin/recall snapshots. Successful import/download resets the form without removing the saved pack. Static application assets require the existing offline worker build step.

## Study-room readiness

The selected room now uses the existing `getRoom` boundary rather than only the lobby collection, refreshes every 5 seconds while visible, and heartbeats every 30 seconds without overlapping requests. The UI distinguishes connection failure, shows retry, separates real participants from open seats, reports completion, and confirms host departure. Successful create/join resets the draft. The lobby tucks away inside a selected room.

Read `integration/STUDY-ROOM-READINESS.md` with the existing OpenAPI and backend-additions handoff. This pass changes no endpoint contract. The source includes a typed HTTP adapter; no real API URL or the backend’s approximately 600-endpoint OpenAPI was supplied, so cross-device rooms were not connected or verified. Device-local preview is labeled and cannot stand in for production multi-user testing.
