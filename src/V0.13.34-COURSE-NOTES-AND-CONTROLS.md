# MedClub V0.13.34 — requested course notes and controls

This complete `src` release builds on the accepted V0.13.33 sources. Replace the
host project's entire `src` directory, retaining its configuration and dependencies.
No package dependency is added. No deployment is included.

## Bell and language feedback

The notification bell now animates a native HTML wrapper, with an SVG bell and
visible ringing marks. Hover, pointer press and click have explicit handlers, and
CSS provides a hover/press fallback. Keyboard focus and activation have feedback.
New arrivals retain their smaller, one-shot motion and first-load/account guards.
Language uses literal A/ع glyphs that exchange positions on hover or keyboard focus.
Movement respects reduced-motion preferences; static feedback remains visible.

## Navigation controls

Public, personal and admin footers now place Appearance before a common status-dot
row. The pin/hide controls overlay that row using absolute positioning and a zero
size layout slot. The row/footer does not grow on reveal, and controls do not shrink
the link scroll area. The status text fades while controls are visible. Keyboard
focus reveals them; touch keeps them accessible. Compact sidebars and horizontal
navigation use the same control order and positioning rule.

## One notes interface

Ordinary notes remain in their existing account-specific store. PDF-linked course
notes remain in the existing versioned margin-note service. Both appear in the same
notes interface in the study tools, course Notes section and general notes utility.
Existing text, course associations, file revisions and anchors are preserved.

- Ordinary note bodies are plain text, with editing available through their action.
- A course note opens its exact PDF/page. Same-course navigation uses the live reader;
  other courses use an encoded course/PDF/page/revision link.
- Clicking a PDF pin opens a small, read-only colored sticker with a close button.
  It does not open the editor. Long sticker text scrolls, with its close control kept
  visible. Clicking a pin also makes its displayed page the active page.
- Course rows have a colored leading edge, PDF/page context and an earlier-revision
  indicator. Existing Amber/Mint/Rose colors remain. The editor border follows the
  chosen color; swatches have a visible selected state and keyboard focus.
- Edit/delete actions reveal on hover or keyboard focus. Touch keeps 44px actions
  visible. Existing swipe deletion, trash flight, undo and recall creation remain.
- The simplified new-note form offers General or Course PDF. Course notes show
  course, PDF and page fields. The PDF toolbar's Add note action fills these from the
  actual open document and active page, including its real page count.
- Ordinary notes keep title/body, download and existing-note autosave. Attached
  notes keep version checks and explicit Save. Switching a new draft to Course PDF
  keeps its title in the body rather than discarding it.

## Errors and persistence

PDF page counts reuse the open reader or parse a selected file without rendering
pages. Missing/changed files, unavailable courses, invalid/out-of-range pages,
password-protected PDFs, load failures, storage failures, version conflicts and
account changes have error/retry states. Failed saves retain the draft. Changed
records are not overwritten during edit/undo. Pending mutations are guarded against
repeat submissions; failed autosave does not retry indefinitely. Unsaved editor
changes require an explicit choice when returning to the list or opening another
draft. Temporary personal PDFs remain session-bound; their note text is retained
when the original file is unavailable.

### API-mode integration

The unified list calls `StudyHubService.listMargins()` with no resource filter.
Local preview supports this and still scopes results to the signed-in owner.
The HTTP adapter now requests `GET /me/margin-notes` for that list. An API host must
support listing the current user's notes without `resourceId`; the existing
`GET /me/margin-notes?resourceId=...` reader requests and write/version contracts
remain supported. No server source was provided or changed. An unsupported list
request shows an error/reload state rather than replacing stored notes.

## PDF and course details

PDF toolbar, close and turn controls have hover/focus tooltips. Close keeps a 44px
cell; very narrow readers use two toolbar rows. Turn handles stay within the middle
of the reading surface, away from close controls, without reducing the PDF canvas.
File sections without materials show a blank-book illustration and quieter binding
and cover depth. Notes/publisher content is not treated as an empty file section.
The course header uses the same stable leather texture as its course cover, with a
matching color wash protecting text contrast. Tool-panel scrollbars use the course
color. Existing course hues, study navigation, zoom, search, bookmarks, theme
switching and the save icons flying toward the profile library remain included.

## Verification and limits

- 43 new executable checks cover attachment validation, account isolation,
  storage failures, course-note CRUD/version conflicts/undo and native bell motion.
- 35 existing executable motion/palette checks pass on these sources.
- All 18 semantic theme variants retain their 270 checked contrast pairs.
- Source syntax, stylesheet structure, relative imports, preserved source bytes and
  ZIP integrity are checked. Cover-wash text contrast is also calculated against
  the brightest possible soft-light texture.
- The save-flight component and stylesheet, existing appearance providers, glass,
  workspace color definitions and ordinary-note storage adapter remain unchanged.

These checks do not establish rendered layout, animation visibility or device
behavior. Full project dependencies/configuration and an executable browser were
not available. A complete strict TypeScript check, production build and rendered
keyboard/touch/RTL testing must run in the host project before deployment. Syntax
checks passed; the available partial strict check is blocked by missing host
dependencies/environment declarations and is not reported as a full type-check pass.
